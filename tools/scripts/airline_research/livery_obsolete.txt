# Liveries that must NOT spawn, keyed by the .obj path relative to apt_aircraft/.
#
# A row here sets that livery's NOTE to "Obsolete" in the generated index, which
# takes it out of the spawn pool at every stage of selection and out of WED's
# preview cards. The .obj itself is NOT touched and library.txt is NOT touched:
# the asset stays on disk and keeps resolving, so scenery that references it by a
# hard path still loads. That is the whole point - deleting the export would fix
# the spawn problem and break the legacy airports at the same time.
#
# gen_livery_index.py merges this file over its own filename-derived notes, so a
# mark survives regeneration. Add rows here, never edit livery_index.txt directly
# for obsolescence - a regeneration would wipe it.
#
# FORMAT: <path under apt_aircraft/> *** <reason>
#   The reason is free text and is for the human reading the diff, not for any
#   parser. Say what supersedes this asset, or why the type no longer flies.
#
# BEFORE ADDING A ROW, READ THE BLAST RADIUS. A mark here is global and has no
# per-stand undo: the livery stops existing at every airport in the world at
# once. gen_livery_index.py prints, for every mark, how many (airline, class)
# pairs it would leave with no asset at all - and a pair with no asset is a stand
# that silently parks nothing. Marking B752 would empty TWENTY pairs; the 757 is
# still in daily service and must never appear here. Run the generator and read
# that number before committing a row.
#
# ============================================================================
# Superseded assets: an old and a new object for the SAME real aircraft are both

# (spec sections 4.4 and 8.4). The "_static.obj" member is the older generation.
#
# These twelve empty ZERO (airline, class) pairs - every one of them has its
# replacement sitting right next to it.
# ============================================================================
