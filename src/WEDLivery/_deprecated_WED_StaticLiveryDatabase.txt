# WED Static Livery Database
# ============================================================================
# WHAT THIS FILE IS: catalogs which specific (airline, aircraft type) livery
# combinations actually exist in the X-Plane resource library, so WED can
# recommend a real, installed livery rather than just an airline name with no
# way to know if a matching aircraft/paint job is actually present.
#
# FORMAT: <AIRLINE_CODE> *** <AIRCRAFT_ICAO> *** <OP_TYPE>
#   - AIRLINE_CODE uses the same code scheme as WED_AirlineDirectory.txt (a
#     confirmed 3-letter ICAO code, an "XP"-prefixed 4-character fictional
#     placeholder, or a "<parent code>_<N>" subsidiary/brand code) - it does
#     NOT get re-derived here, just referenced.
#   - AIRCRAFT_ICAO is the aircraft type designator (A21N, B738, ...) - look
#     it up in WED_AircraftSizeReference.txt (same folder) to get its ramp
#     size class; this file does not repeat the size class itself, to avoid
#     the two files disagreeing with each other if a size gets corrected.
#   - OP_TYPE is one of: Airline, Cargo, GA, Military (matches
#     WED_LiveryOpType in WED_LiveryData.h). This is the actual source of
#     truth for that classification - NOT WED_AirlineDirectory.txt, which
#     has no op_type field at all (see its own header comment).
#
# One row per (airline, aircraft type) combination that has a real, installed
# livery - an airline with liveries for three aircraft types gets three rows.
#
# STATUS: DEPRECATED - never populated, superseded before it carried any data.
# Kept (renamed with the _deprecated_ prefix) only so the reasoning below stays
# findable; nothing loads it and nothing should.
#
# SUPERSEDED BY: livery_index.txt, which lives on the X-PLANE side at
#   <X-Plane root>/Resources/default scenery/sim objects/apt_aircraft/livery_index.txt
#
# WHY IT MOVED OUT OF WED: this file was going to catalogue which (airline,
# aircraft type) liveries exist, but that inventory is a property of the
# X-Plane installation, not of WED. Putting it here would have meant WED
# shipping its own opinion about another product's asset library and going
# stale the moment X-Plane shipped a new livery. On the X-Plane side it sits
# next to the assets it describes, so the PR that adds a livery is already
# touching that directory. WED reads it through the X-Plane root the user has
# already selected (gPackageMgr->GetXPlaneFolder()) - which is a hard
# prerequisite for loading any livery at all, so the dependency costs nothing.
#
# The replacement also carries more than this file's three columns: aircraft
# type, operator, registration, country of registration, and a livery note
# (Default / Retro / Special / Alliance / Government / Unpainted). See
# WED_ProjectNotes.md in the repo root for how the pieces fit together.
